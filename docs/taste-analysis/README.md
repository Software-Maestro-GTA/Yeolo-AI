# 단일 호출 취향 분석 (2026-10-03)

Yeolo-AI는 기존 사진 메타데이터 요청을 유지한다. 사진 수집은 Yeolo-FE, 장소·계절 전처리는 BE의 책임이다.

## 실행 흐름

1. 사진 ID 중복을 제거하고, timezone이 있는 촬영 시각과 확인 가능한 장소가 있는 기록만 사용한다. 모두 무효면 스트림과 LLM 호출 전에 HTTP 400을 반환한다.
2. 정규화된 국가·도시·지역·행정구역·장소명과 입력 offset 기준 날짜로 구분한다. 첫 사진부터 2시간 이내를 한 방문으로 묶는다. 연속 촬영으로 방문 창을 계속 늘리지 않는다. 같은 방문의 장소 유형은 집합으로 집계한다.
3. 방문 수, 날짜·장소 다양성, 유형·계절 분포, 항목별 방문·날짜 근거를 JSON으로 생성한다. 사진 수는 선호 강도가 아니라 표본 품질 정보다. 사용자/사진 ID, 개별 촬영 시각과 장소명 목록은 LLM 입력에 넣지 않는다.
4. 통계를 단일 LLM 체인에 전달해 전체 취향 프로필을 구조화 출력으로 받는다. 분석 전용 스키마는 계절·환경 목록에 최소 1개를 요구한다. 별도 Fact Sheet 생성, 3개 병렬 채점 및 온라인 LLM 평가 호출은 없다.
5. 코드로 점수·호환값을 보정하고 계절·환경 선택을 확정한다. 잘못된 LLM 값이나 서비스 오류를 성공 결과로 위장하지 않는다. 제공자/구조화 출력 오류는 기존 SSE error로 처리한다.
6. 성공 응답은 API-AI-1대로 `complete.data.tasteProfile`만 포함한다. `analysisMetadata`는 공개 응답에서 제외하고 활성 LangSmith trace에 내부 관측 정보로 기록한다.

## 점수 보정

항목에 매핑된 방문 3회 이상과 서로 다른 날짜 2일 이상일 때만 LLM의 4–5점을 유지한다. 나머지는 3점으로 보정한다. 기록이 없다는 사실은 비선호가 아니며, 사진 방문 정보만으로 싫어함을 확정할 수 없어 1–2점도 3점으로 보정한다.

동행·소비·일정 밀도는 `solo`, `moderate`, `balanced` 호환 기본값을 유지한다. 실제 사용자 선호를 확인한 값은 아니다. confidence의 low/medium은 미검증 근거 휴리스틱이고 정확도 확률이 아니다.

## 계절·환경 최소 1개 정책

기존 DOM-2의 8개 enum을 유지한다. 최종 선택은 LLM의 빈 목록이나 불안정한 선택에 의존하지 않고 방문 통계로 결정한다.

- 반복 관측 후보: 여름 beach/resort_hotel → `summer_resort`, 겨울 ski_resort → `winter_sports`, 봄·가을 botanical_garden → `spring_flower_autumn_foliage`. 3회·2일 기준을 충족하는 후보를 반환한다. 식물원 유형도 꽃·단풍 관람 목적을 확정하지 않는 휴리스틱이다.
- 반복 근거가 없으면, 관측된 위 활동 후보 중 방문·날짜 근거가 가장 강한 하나를 잠정 선택한다.
- 활동 후보도 없으면, 가장 많이 관측된 촬영 계절에 따른 UI용 잠정값을 하나 반환한다. 여름은 `warm_region`, 겨울은 `cold_region`, 봄·가을은 `spring_flower_autumn_foliage`다. 동률은 고정 순서로 결정하며 입력 순서에 의존하지 않는다.
- 약한 관측이나 계절 기본값은 low confidence, insufficientEvidence 및 선택/보정 사유를 내부 metadata에 기록하고 사용자 확인 대상으로 취급한다. 여름 사진이 실제 따뜻한 기후 선호를 입증하는 것은 아니다.
- 기후·날씨·목적지별 성수기 정보가 없으므로 `dry_weather`, `off_season`, `peak_season` 등을 확정하지 않는다. 봄·가을 카페 기록에서 나온 계절 기본값도 꽃·단풍 활동 관측과 구분한다.

이 정책은 UI에 최소 한 항목을 제공하기 위한 제품 정책이다. 정확도 향상 자체를 입증하는 규칙은 아니다. 공개 API에 신뢰도 필드가 없어 FE/BE는 현재 프로필만으로 잠정값을 구분할 수 없다. 사용자 확인과 잠정값 표시를 연결하려면 후속 계약 검토가 필요하다.

## 내부 관측과 검증

내부 `analysisMetadata`에는 statistics, fieldEvidence, fallbackFields, requiresUserConfirmation과 계절 선택 근거를 기록한다. LangSmith 추적이 비활성화된 환경에서는 이 정보가 원격 저장되지 않는다. 추적 저장 실패로 정상 분석을 중단하지 않는다.

회귀 테스트는 단일 LLM 호출, SSE 계약, 오류 경로, 방문 집계 불변성, 점수 보정, 계절 목록 최소 1개 및 잠정값 표시를 검증한다. 이전 `live-verification-2026-10-03-network` 기록은 4회 호출 구조의 과거 실행 결과이며 이번 구조의 검증으로 해석하지 않는다.

사진 선택 편향, 생활/여행 기록 혼재, 장소 전처리 품질 및 사용자별 실제 선호는 별도 평가가 필요하다. 방문 창 2시간, 반복 근거 3회·2일, 전체 표본 충분성 10일·15곳 기준은 사용자 평가로 조정해야 한다. 기존 프로필의 누적 저장/학습은 이번 범위에 포함하지 않는다.

LangSmith 원격 기록에서 각각 LLM 호출 1회와 내부 analysisMetadata를 확인했다. 전체 API·추적 확인 시간은 12.65초/13.94초, 사용 토큰은 2,421/2,873이었다. 상세 합성 입력과 결과는 `live-verification-single-call-2026-10-03/`에 보존했다. 이 결과는 실행 및 보정 규칙의 검증이며 실제 선호 정확도 평가가 아니다.
