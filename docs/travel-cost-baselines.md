# 여행 교통·숙박 기준가격

## 목적과 가격의 의미

항공·숙박 공급자 조회가 실패해도 필요한 여행 비용이 `totalCost`에서 사라지지 않도록 계획 금액을 제공합니다. 실제 조회 가격이 있으면 해당 금액을 우선하고, 빠진 항목에만 기준가격을 사용합니다.

**아래 금액은 초기 서비스 정책 추정값입니다. 국가별 실거래 평균, 수집된 통계, 특정 상품의 판매가가 아닙니다.** `estimated` 상태로 보관하며, 실제 조회 결과인 `available`과 구분합니다. 장소별 식사·입장료 추정과도 별개입니다.

- 구현: `app/services/travel_cost_baselines.py`
- 정책 버전: `travel-cost-policy-v1`
- 기준일: `2026-10-19` — 이 정책의 작성일이며 가격을 실측한 날짜가 아닙니다.
- 통화: KRW. 별도 환율 환산 없음.
- 추가 네트워크·LLM 호출, 다운로드 파일, 외부 CSV, 추가 의존성 없음.

## 적용 조건

| 항목 | 기본 조건 |
| --- | --- |
| 출발 | 서울. 해외 항공은 인천(ICN), 국내 항공은 김포(GMP) 기준 |
| 인원 | 성인 1명. 유효한 설정 인원이 있으면 왕복 교통에 곱함 |
| 숙박 | 객실 1개, `여행 일수 - 1`박 |
| 해외 | 왕복 항공 + 숙박 |
| 제주·서귀포 및 확인된 제주 권역 | 왕복 항공 + 숙박 |
| 그 외 국내 | 왕복 철도·버스 계획 금액 하나 + 숙박 |
| 서울 자체 여행 | 시외 왕복 교통 제외, 숙박은 여행 일수에 따라 적용 |
| 당일 여행 | 숙박 제외, 필요한 왕복 교통은 포함 |

국내 `ground`는 철도·버스로 이동할 때 쓸 계획 금액입니다. 실제 열차·버스 노선이나 예약 가능 여부를 확인한 결과는 아닙니다. 수하물·추가 옵션, 예약 수수료를 별도 상품으로 산출하지 않습니다. 일정에 연결된 공항·숙소 이동은 실제 확인된 교통 요금만 합산합니다. 여행 인원·객실 수·출발지는 현재 공개 요청에 없으므로 실제 사용자 조건과 다를 수 있습니다.

국가는 Maps가 확인한 ISO 국가 코드로만 선택합니다. 도시 이름은 확인된 도시명을 우선하며, 이름이 없을 때만 요청 도시명을 사용합니다. 문자열을 정규화한 뒤 국가 코드와 함께 정확히 비교합니다. 미등록 도시는 국가 기준, 미등록 국가는 공통 기준을 사용합니다. 도시가 실제로 존재한다는 검증은 Maps에서 수행하며, 이 가격표의 이름 목록은 장소 검증에 사용하지 않습니다.

## 생성 순서와 합산

`prepare`에서 목적지를 확인한 뒤 `quote_trip`에서 왕복 교통·전체 숙박 비용을 확보합니다. 실제 견적이 없는 항목은 기준가격으로 보충하고, 그다음 `draft`에서 남은 예산으로 관광·식사와 공항·숙소 후보를 함께 생성합니다. `resolve_anchors`는 공유 공항·숙소를 검증하고 가격을 연결합니다. 이때 선택 장소가 견적의 장소와 달라지면 해당 기준가격으로 교체하여, 이후 장소 후보 선택·비용 검증에 수정된 잔여 예산을 사용합니다.

```text
prepare → quote_trip → draft → resolve_anchors → verify_places
→ verify_routes → schedule → finalize → attach_lodging → attach_airports
→ localize_display → finalize_course
```

```text
활동 예산 = max(0, 요청 예산 - 왕복 교통비 - 전체 숙박비)
일별 장소·식사 목표 = 활동 예산 / 여행 일수
totalCost = 장소별 예상 비용 + 확인된 구간 이동 요금 + 왕복 교통비 + 전체 숙박비
```

항공과 숙박은 같은 견적 단계에서 병렬 조회하며, 각 항목의 실조회 금액을 독립적으로 보존합니다. 실조회와 기준가격을 중복 합산하지 않고, 전체 숙박 견적에 박수를 다시 곱하지 않습니다. 필수 비용이 요청 예산을 넘더라도 장소 수나 필수 식사를 줄여 코스를 실패시키지 않습니다.

## 숙박일 마지막의 숙소 표시

확정한 관광·식사 일정 뒤에 `attach_lodging`, `attach_airports` 노드를 실행하고, 이후 기존 `localize_display` 노드에서 숙소·공항 이름과 이동 안내도 함께 현지화합니다.

- 2박 3일은 1·2일차 마지막에 같은 숙소를 추가합니다. 마지막 체크아웃 날짜와 당일 여행에는 추가하지 않습니다.
- 숙소는 관광·식사 최소 방문 수를 대신하지 않습니다. 반복 숙박은 관광 장소 중복 검사와 SQLite의 관광 이력에 포함하지 않습니다.
- 공급자 숙소는 MyRealTrip 검색의 `gid`·호텔명을 같은 날짜·인원·지역의 상세 응답과 연결합니다. 요금만 없으면 검증된 이름과 기준 숙박비를 함께 유지할 수 있습니다. 다른 숙소·지역·날짜·인원 또는 명시적 매진 응답은 이 공급자 견적으로 사용하지 않습니다. 공급자 정보가 없거나 위치 검증에 실패하면 별도로 생성한 숙소 후보를 검증합니다. 생성 후보의 객실 예약 가능 여부는 확인하지 않으며, 특정 호텔의 실제 객실 가격으로 기준 숙박비를 표현하지 않습니다.
- 호텔명과 확인된 도시·국가로 Text Search IDs Only를 호출하고, 첫 검색 ID의 Essentials 상세로 실제 숙박 유형·국가·도시 범위·주소·좌표를 검증합니다. 공급자의 `gid`를 Google `placeId`로 사용하지 않습니다. 공식 표시 이름이나 객실을 Google에서 추가 조회하지 않습니다.
- 마지막 방문 장소에서 숙소까지 실제 경로를 조회하고, 확인하지 못하면 `unknown`으로 반환합니다. 실제 90분 초과 경로만 확보되면 숙소 추가를 보류하며, 이 경로를 짧은 추정값이나 `unknown`으로 바꾸지 않습니다.
- 숙소 위치를 확인하지 못하면 기존 관광·식사 코스를 반환하고 진행 메시지로 숙소 미추가를 안내합니다. 숙소를 찾기 위한 추가 LLM 요청은 없습니다.

### 공개 응답과 앱 연결

기존 `days[].stops[]` 구조를 사용하며 `place.category`에 **`LODGING`**을 추가합니다. BE·FE의 enum과 아이콘·표시 처리가 이 값을 허용해야 합니다.

| 필드 | 숙소에서의 의미 |
| --- | --- |
| `sequence` | 해당 날짜의 마지막 순번 |
| `stayMinutes` | 입실·정리를 위한 계획 시간 30분. 수면 시간·확정 체크인 시간은 아님 |
| `cost` | 전체 숙박비를 N-1박에 나눈 표시 금액. 정수 나눗셈 잔액을 배분하여 합계 일치 |
| `reason`·`memo` | 같은 숙소를 거점으로 머무는 이유, 예약 전 확인·도착 준비 팁. 예약 완료·시설·조식 포함을 주장하지 않음 |
| `transportToNext` | 마지막 숙소는 `none`, 직전 장소에 숙소로 돌아오는 이동 정보를 연결 |

숙소 `cost`의 합계는 이미 `totalCost`에 포함한 숙박비를 보여주는 것입니다. 총액에 숙박비를 다시 더하지 않고 새 귀가 구간의 **확인된 교통 요금만** 추가합니다. 기준가격을 썼다면 특정 호텔의 확정 객실 가격이 아니라는 기존 추정 상태를 유지합니다.

추가 Google 사용량은 정상적인 한 숙소 연결에서 IDs Only 검색 1회, Essentials 상세 1회와 숙박일당 귀가 경로 조회가 기본입니다. 실제 재시도·이동수단 대안에 따라 경로 호출 수는 늘 수 있습니다. 한 요청에서 확인한 숙소 위치는 모든 숙박일에 재사용하며 사진·Pro 필드는 요청하지 않습니다.

## 관광 후보와 공항·숙소 후보를 함께 생성

- 기존 일별 LLM 요청 중 한 요청에만 여행 전체의 `anchor_candidates`를 함께 요청합니다. 공항 후보는 실제 이름·영문명·IATA 코드, 숙소 후보는 실제 이름·영문명을 각각 최대 2개 제안합니다. 이 데이터는 **검증 전 후보**입니다.
- LLM은 좌표·Place ID·객실 재고·항공편 운항·예약 가능 여부를 만들지 않습니다. 숙소는 국가·도시·전체 관광 권역·1박 계획 금액에 맞춰 제안합니다. 항공 이동이 아니면 공항, 당일 여행이면 숙소를 제외합니다.
- 관광·식사 후보 수와 기존 LLM 호출 횟수·토큰 상한·시간 제한을 유지합니다. 공항·숙소가 관광 최소 5곳을 대신하지 않습니다. 후보용 텍스트가 추가되므로 실제 사용 토큰까지 동일하다는 의미는 아닙니다.
- 공유 후보는 일부 날짜의 응답 실패와 재시도 사이에 유지합니다. 선택적 후보의 형식 오류만으로 정상 관광 후보 전체를 버리거나 LLM을 다시 호출하지 않습니다.
- `resolve_anchors`에서 공항과 숙소를 병렬로 확인합니다. 공급자 식별 정보가 있으면 우선 검증하고, 없거나 검증에 실패하면 생성한 대안을 확인합니다. 각 종류별 장소 검증 시도는 공급자 포함 최대 2개입니다. **예약 가능 여부는 생성 후보 사용의 필수 조건이 아닙니다.**
- 성공한 공항·숙소는 날짜 복구와 최종 일정 연결에서 재사용합니다. 공항을 아직 확보하지 못한 상태에서 기존 날짜 복구가 새로운 IATA 후보를 만들면 남은 조회 횟수 안에서만 추가 검증합니다. 공항 검증은 요청 전체에서 최대 2회이며 이미 시도한 코드는 이후 복구에서 반복하지 않습니다. 공급자 공항에 실패하면 같은 공항의 반복 후보보다 다른 공항 후보를 먼저 확인하고, 이름·영문명까지 동일한 후보는 다시 조회하지 않습니다. 모든 후보가 미확보이면 해당 장소만 생략하고 기존 관광 코스는 보존합니다.
- 생성 숙소를 선택했다면 다른 호텔의 실조회 가격을 붙이지 않고 기준 숙박비를 사용합니다. 생성 공항은 실제 항공 견적의 국가·IATA가 정확히 같은 경우만 기존 항공료를 유지하며, 다른 공항이면 기준 항공비로 교체합니다. 기존 금액에 새 금액을 더하지 않습니다.

Maps 조회는 기존 ID 검색·Essentials 상세·요청 캐시를 사용합니다. 정상 선택은 각 장소를 한 번 검증하며 최종 일정 연결에서 재조회하지 않습니다. 대안 후보가 필요한 경우에만 검증 요청이 늘어납니다. 기존 공개 요청·응답 필드와 SSE 이벤트는 유지합니다.

## 첫날·마지막 날 공항 표시

항공을 이용하는 해외·제주 코스에서 **첫날 첫 장소는 도착 공항**, **마지막 날 마지막 장소는 귀국·복귀 공항**으로 연결합니다. 출발지 인천·김포를 여행지의 장소 목록에 넣지 않습니다. 철도·육상 이동 코스에는 공항을 추가하지 않습니다.

```text
finalize → attach_lodging → attach_airports → localize_display → finalize_course

2박 3일 예시
1일차: 도착 공항 → 관광·식사 → 숙소
2일차: 관광·식사 → 같은 숙소
3일차: 관광·식사 → 출발 공항
```

- 공급자 공항은 MyRealTrip의 국가·도시·IATA 검증을 통과한 실제 항공 검색의 목적지이며 선택한 운임과 공항 정보를 함께 보존합니다. 공급자 정보가 없거나 위치 검증에 실패하면 생성 후보를 검증해 추천 공항으로 사용할 수 있습니다. 생성 후보를 선택했다는 사실만으로 실제 항공편이 조회되었거나 예약 가능하다는 의미는 아닙니다.
- 공식 공급자 [공항 자동완성 계약](https://docs.myrealtrip.com/llms-full.txt)의 `airport.code`, `airport.koName`, `airport.enName`을 사용합니다. 공항 CSV나 추가 LLM 검색은 없습니다.
- 공항명·국가와 IATA·국가로 각각 Text Search IDs Only 검색을 하고 첫 ID가 일치해야 합니다. 이름 검색이 실패하거나 터미널 등 다른 ID가 먼저 나오면 제공된 영문명으로 ID 검색을 최대 1회 추가합니다. 영문명의 첫 ID가 IATA의 첫 ID와 일치할 때만 복구하며, 이때 표시 이름도 검증에 성공한 영문명을 기존 번역 노드에 전달합니다. 검색 목록에 같은 ID가 있다는 이유만으로 다른 공항 이름을 붙이지 않습니다. 그 ID의 Essentials 상세로 실제 공항 유형·국가·주소·좌표를 검증합니다. 나리타처럼 도심 밖에 있는 공항은 이 전용 검증에서 허용합니다. 생성 후보는 추가로 확인된 도시 경계에서 직선거리 200km 이내여야 합니다(날짜 변경선 지원). 이는 후보 제외 기준이며 실제 이동 거리·운항·도시 연결을 보장하는 값이 아닙니다. 관광·숙소의 도시 범위 검증은 유지합니다.
- 공항 위치는 한 번 확인해 양 끝에서 재사용하고, 도착 공항→첫 방문지·마지막 방문지→공항을 병렬 조회합니다. 대중교통·택시 등 실제 대안을 시도하고 실패하면 해당 구간을 `unknown`으로 둡니다. 공항 이동은 관광지 간 90분 제한을 적용하지 않고 측정된 장거리 이동을 그대로 보존합니다.
- 기존 관광·식사 장소를 줄이지 않으며, 공항은 최소 방문 수·다양성 이력에 포함하지 않습니다. 당일 항공 여행은 같은 날짜 양 끝에 공항이 들어갑니다.
- 공항을 확인하지 못하면 기존 코스를 유지하고 진행 메시지로 공항 미추가를 안내합니다. 공유 장소 검증과 최종 공항 이동 연결은 각각 최대 12초와 남은 요청 시간 중 짧은 쪽으로 제한하며, 사용자 취소는 즉시 전파합니다. 이미 검증한 공항은 마지막 경로 조회 시간이 부족해도 양 끝에 유지하고 미확보 이동 정보만 `unknown`·null로 반환합니다. 공항 미확보·후보 소진·검증 불일치·경로 시간 부족은 서버 로그에서 구분합니다.

### 응답·비용·시간의 의미

`place.category`에 **`AIRPORT`**를 추가합니다. BE·FE의 enum·아이콘 처리가 필요하며 공개 응답 구조와 SSE 이벤트는 동일합니다. 이름과 이동 안내는 기존 번역 호출에 함께 포함합니다.

첫날 공항 stop의 `cost`에는 가는 편, 마지막 날 공항 stop의 `cost`에는 오는 편의 **항공료 예상 배분액**을 표시합니다. 공급자가 제공하는 금액은 왕복 총액이므로 두 항목에 절반씩 나누며, 홀수 1원은 가는 편에 배분합니다. 두 `cost`의 합은 왕복 금액과 정확히 같습니다. 당일 여행도 같은 날 양 끝의 두 공항 항목에 각각 표시합니다.

- 항공권 API 조회 성공: 검증된 왕복 조회 금액을 배분합니다. 별도의 편도 가격을 조회한 것이 아니므로 실제 개별 항공권 가격으로 표현하지 않습니다.
- 항공권 API 조회 실패·검색 결과 없음·시간 초과: 기존 도시 → 국가 → 공통 기준의 왕복 예상 항공료를 배분합니다. 해외 기본 출발지는 인천이며, 선택 공항이 실조회 견적의 공항과 다르면 그 견적을 재사용하지 않고 기준가격을 적용합니다. 제주 등 국내 항공은 기존 김포 출발 정책을 유지합니다.
- 현재 노선별 실측 평균 운임 데이터는 없습니다. 기준가격은 **선택 공항으로 여행하기 위한 목적지 도시·국가 기준 추정**이며, 인천–해당 공항 노선의 실측 평균이나 확정 판매가가 아닙니다. 추가 평균가 조회 API·LLM·외부 CSV를 사용하지 않습니다.
- 예: 도쿄의 일반석 기준 왕복 350,000원을 적용한 경우, 첫날 175,000원 + 마지막 날 175,000원으로 표시합니다. 왕복 조회가 410,123원이면 첫날 205,062원 + 마지막 날 205,061원입니다.

왕복 항공료는 이미 장소 생성 전 예산에서 차감하고 `totalCost`에 한 번 포함합니다. 공항 `cost`는 그 금액의 표시이므로 총액에 다시 더하지 않으며, 추가된 공항 이동 구간의 확인된 교통 요금만 더합니다. 숙박비도 다시 합산하지 않습니다. 앱에서 항공 항목은 **가는 편/오는 편 예상 비용**으로 표시하고, BE가 AI 응답의 `totalCost`에 공항·숙소 `cost`를 다시 더하지 않도록 합니다. 요청·응답 필드와 SSE 이벤트는 동일하고 `cost`의 공항 표시 의미만 변경됩니다.

`stayMinutes`는 도착 시 정리 60분·출발 준비 120분의 **일정용 여유 시간**입니다. 항공편 출도착 시각·터미널·항공사 수속 마감은 현재 조회 결과에 없으므로 생성하지 않으며, 실제 항공편에 맞춘 일정 시간 검증도 하지 않습니다. 따라서 마지막 관광 이후 항공편을 탈 수 있다고 보장하는 시간표가 아닙니다. `memo`에서 실제 항공편과 항공사의 수속 안내에 맞춰 시작·종료 시간을 잡도록 안내합니다.

공항 추가의 일반적인 Google 사용량은 IDs Only 검색 2회, Essentials 상세 1회, 공항 이동 경로 2회입니다. 캐시·조회 실패·모드 대안·재시도에 따라 실제 호출 수는 달라집니다. Pro 상세·사진 요청은 없습니다.

## 상품 수준 선택

1. 교통에 전체 예산의 35%, 숙박에 25%를 **선택 한도**로 사용합니다.
2. 고정된 상품 수준별 금액 중 한도 안에 들어오는 가장 높은 수준을 선택합니다.
3. 가장 낮은 수준도 한도를 넘으면 그 금액을 그대로 유지합니다. 예산에 맞추려고 가격을 낮추거나 0원으로 만들지 않습니다.
4. 실제 조회된 교통·숙박 금액이 있으면 해당 기준가격을 교체합니다. 두 가격을 합산하지 않습니다.
5. 최종 교통·숙박 합계를 전체 예산에서 뺀 금액이 식사·관광의 활동 예산입니다. 전체 예산을 초과하면 활동 예산 목표는 0원이지만 코스 생성을 막지 않습니다.

예를 들어 도쿄의 기준 왕복 항공은 일반석 35만 원, 비즈니스 120만 원 중 하나입니다. 사용자가 예산을 조금 올렸다는 이유로 같은 일반석 가격이 36만 원으로 늘어나지 않습니다. 실제 판매상품을 조회하지 못한 경우, 비즈니스 수준을 선택했다는 사실은 특정 항공편이 그 금액으로 판매됨을 의미하지 않습니다.

## 실조회와 추정 구분

내부 가격 항목에는 `status`, `amount_krw`, `reason`, `source`, `reference_date`를 보관합니다. 기준가격의 `source`는 예를 들어 `travel-cost-policy-v1:JP/tokyo`입니다. 교통수단은 `transport_mode`의 `air`, `ground`, `none`으로 구분합니다.

기존 내부 `TripQuotes.flight` 슬롯은 왕복 교통 금액을 담습니다. 국내 철도·버스는 `transport_mode=ground`이므로 항공료로 해석하면 안 됩니다. 이 경우 공급자가 반환한 관계없는 항공료로 교체하지 않습니다. 숙박 실조회는 교통수단과 무관하게 독립적으로 우선 적용합니다.

현재 공개 API는 항목별 비용·추정 여부 없이 숫자 `totalCost`를 전달합니다. 완료 전 진행 메시지에는 기준가격을 사용한 항목을 안내하고, 서버 로그에는 상태·금액·정책 출처·작성일을 남깁니다. 향후 BE·FE와 합의한 비용 내역 필드를 통해 실제 조회/추정, 교통수단, 인원과 객실 조건을 전달할 수 있습니다.

## 한계와 갱신

- 계절, 예약 시점, 휴일, 환율, 특정 상품의 잔여 객실·좌석을 반영하지 않습니다.
- 1객실 고정이므로 인원이 많을 때의 객실 수·수용 인원 검증을 하지 않습니다.
- 등록되지 않은 도시에는 해당 도시만의 물가 차이가 반영되지 않습니다.
- 기준가격은 실제 평균가가 아니므로 “평균 항공권 가격 조회 완료”와 같은 문구를 쓰지 않습니다.
- 값 변경은 코드 리뷰로 수행합니다. 금액·선정 이유·버전·작성일·표·회귀 테스트를 함께 갱신합니다. 새 정책의 금액은 사용자의 요청 예산에 비례해 생성하지 않습니다.
- 추후 출처가 있는 집계 데이터나 운영 견적 통계가 마련되면, 기간·표본 수·통화·인원·상품 수준이 명확한 통계로 대체할 수 있습니다. 외부 스냅샷을 자동 다운로드하거나 최신 데이터라고 가장하지 않습니다.
