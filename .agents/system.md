# 하네스 공통 규칙

이 문서는 프로젝트 작업 지침입니다. 호스트의 시스템·개발자 지침과 사용자 요청을 우선하며, 파일에 적힌 권한 설정으로 실제 도구 권한을 확대하지 않습니다.

## 범위와 기록

- 사용자 요청과 기존 변경사항을 확인합니다. 사용자 작업을 되돌리거나 무관한 파일을 함께 정리하지 않습니다.
- 별도 역할을 위임한 경우 해당 담당 범위를 지킵니다. 단일 에이전트 작업에서는 필요한 구현·테스트·문서를 함께 수정할 수 있습니다.
- 사용자가 하네스 수정을 요청했다면 요청 범위의 수정은 이미 승인된 것입니다. 같은 수정을 다시 승인받기 위해 작업을 멈추지 않습니다.
- `.agents/Yeolo-SPEC/`는 읽기 전용 참조입니다. 사용자 요청 없이 서브모듈을 수정하거나 갱신하지 않습니다.
- 기존 `progress.md`, `log.md`를 초기화하지 않습니다. 기록이 필요하면 기존 내용을 보존하고 현재 작업 구역만 갱신합니다. 없는 이슈 번호나 에이전트 수행 이력을 만들지 않습니다.
- 커밋·푸시는 각각 사용자 요청이 있을 때만 수행합니다. 수정 요청을 커밋 요청으로 해석하지 않습니다.

## 도구와 스킬

- 작업에 필요한 스킬만 파일 읽기 도구로 읽습니다. 이미 읽은 스킬을 반복해서 로드하지 않습니다.
- 패키지는 uv로 관리합니다. 기존 환경 준비는 `uv sync --locked`, 의존성 변경은 `uv add`와 잠금 파일 갱신을 사용합니다.
- 검증 명령은 `.agents/AGENTS.md`를 따릅니다. 설치된 환경이나 권한이 부족하면 실행 실패를 그대로 보고하고 성공으로 표시하지 않습니다.

## 검증의 의미

- 검증 후 코드·테스트·의존성·실행 설정을 수정했다면 영향을 받는 검증을 다시 실행합니다. 이전 성공을 최종 변경사항의 검증 결과로 보고하지 않습니다. 문서만 수정한 경우에는 하네스 문서 검사를 다시 수행하면 됩니다.

- 실제 명령, 범위, 종료 코드에 근거해 결과를 기록합니다. 선택 테스트 통과와 전체 테스트 통과를 구분합니다. 테스트 수를 코드 커버리지로 표현하지 않습니다.
- Ruff는 린트 검사입니다. 별도 타입 검사 명령을 실행하지 않았다면 TYPE은 미구성 또는 미실행입니다.
- 변경 목적을 검증하는 테스트를 유지합니다. 삭제·통합 전에는 각 테스트가 검증하던 분기와 대체 검증을 확인합니다. API 직렬화 문제는 실제 SDK 요청을 네트워크 없이 확인합니다.
- 실패는 기존 실패, 새 회귀, 환경 문제로 구분합니다. 통과시키기 위해 assertion을 약화하거나 mock으로 결함을 감추지 않습니다.
- 같은 실패에 근거 없는 재시도를 반복하지 않습니다. `config.json`의 `max_tdd_loops`는 에이전트가 수정·재검증 반복을 점검하는 상한 가이드이며 자동 실행 제한이 아닙니다. 도달하면 원인과 남은 작업을 설명하고 접근을 재검토합니다.
- 상세 진단은 터미널에서 확인합니다. 기록에 필요한 오류 부분만 요약하고 자격 증명·개인정보를 복사하지 않습니다. 훅은 명령과 상태만 기록합니다.
